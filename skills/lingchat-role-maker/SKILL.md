> 实战蒸馏自完整跑通的项目：FGO 角色梵高（日配 + 6 套立绘服装 + 自定义语音模型）、但丁（日配 + 5 套立绘服装 + 自定义语音模型）。

## 0. 总览与速通准备

### 0.1 本 Skill 适用性（先判断再往下走）

- **目标产物**：在 AI 助手辅助下，快速复刻 FGO 从者角色（参照已跑通的**梵高**成品）——**静态立绘 + 20 情绪差分 + 独立训练的日语语音模型**。
- **⚠️ 不适合本 skill 的用户**：不是做 FGO 角色、**不想自己训练语音模型**（只想用现成 TTS）、不想折腾的用户——直接告知用户本 skill 不适用，不要硬套流程。
- **默认包含自训语音模型（无跳过分支）**：加载本 skill 即代表用户**接受训练语音**——需要下载 FULL 训练包（约 5G，0.5）并跑数小时训练（3.1）。**本 skill 没有「用现成声音跳过训练」的捷径**，执行时不要再提供此类选项（与 0.7 一致）。
- 「速通」指**流程走通快、按路线图一气呵成**，不是全流程几十分钟完成：语音训练是最大耗时项（数小时级，取决于数据量与显卡），差分手动部分也需要时间。

### 0.0 执行启动流程（加载本 Skill 后的固定动作，按顺序做）

> 目的：把「加载 Skill → 开始干活」之间的步骤写死，避免遗漏关键准备（检查本机 / 问清需求 / 建交接清单）。

1. **通读本 SKILL + references 全套**：核心四件——`settings_van_gogh.yml`（settings 母版）、`voice_models_20字段.md`（20 字段清单）、`avatar_情绪文件名清单.md`（情绪命名参考）、`role_handoff_checklist_template.md`（交接清单模板）；另有补充——`settings_dante.yml`（【主线剧情的记录】板块写法参考）、`README.md`（索引与待补清单）。
2. **检查本机**：LingChat / ffmpeg / 整合包（`VoiceSpeechMaker-core-fork`）是否已装（`Test-Path` 或搜 D 盘常见目录）——避免让用户重复下载（0.7 询问技巧）。
3. **一次问清 0.7 的六项问题**（角色名含其他形象 / 自训语音确认 / 做几个形象 / 表情图工具 / ffmpeg / LingChat 安装方式），不中途追加关键询问。
4. **复制交接清单**：把 `references/role_handoff_checklist_template.md` 复制为 `<角色名>_交接清单.md`，随进度逐项勾选（0.3 第 3 条 / 0.7）。
5. **🛑 过「开爬闸门」再动手（硬性停止检查点，0.3.3）**：爬取前逐项核对——**0.7 六项问题是否全部问完？用户是否明确许可开工？两个条件都满足才放行**；未过闸门禁止任何爬取/联网动作（搜索角色名、抓语音页/资料页、下载文件都不行），继续等用户回复。
6. **开爬**：Agent 侧开工——爬语音页 + 资料页留档（1.4；**外网站点抓取前先看 0.8 网络访问与代理，已内联、无需外部 skill**，fgo.wiki 等国内站可直连），同时向用户交代其侧任务（并行任务分配见交接清单阶段 1）。

> **⚠️ pro 版默认不加载**：`lingchat-role-maker-pro` 是进阶扩展，**只有用户明确提出进阶需求**（全量语音补全 / BGM 补充语料 / 立绘补全 / 语速调优 / 本地 TTS / 手机端 / 排障踩坑大全）时才加载；无需求全程只用本速通版，**不要主动加载 pro**。

### 0.2 前置条件（用户侧，缺一不可，开始前先确认）

1. **梯子（科学上网）必装**：没有就让用户先解决再继续（哪些站必须走梯子见 0.4 表格）。
2. **有文件修改写入权限的 AI 助手**：本流程大量写文件（脚本、yaml、目录结构、素材下载），Agent 没有写入权限无法执行，建议全程开启最高级别的读写权限。本 skill 的原生运行环境是 DeepseekHarness（dsh），但网页/App 版 Deepseek 只能提问不能操作文件，codex、claude 等本地/云端 Agent 均可替代，也有 **Trae、workbody 等免费软件可平替**——核心要求是**能写文件 + 能联网搜索/爬取**。语音与资料由 Agent 直接从 **Mooncell（FGO 中文 Wiki，网址 fgo.wiki）** 爬取，**用户只需说出角色名，不需要自己找资料**。
3. **LingChat 本体**：从 GitHub Releases 下载编译好的安装包安装（见 0.4）。**注意：这是「下载」不是「克隆」**——不要 `git clone` 源码自己编译（需要 pnpm + Rust 工具链，耗时且易踩环境坑），除非用户明确要改源码；建议用户自己去找适合自己系统的版本下载安装。
4. **语言大模型 API key（至少一个，必需）**：LingChat 对话由 LLM 驱动，没有 key 角色无法开口聊天——在软件设置里配置（见 4.0）。**视觉大模型 API key 可选择使用**（可选配，不开也能用，只是少图像理解能力）。

### 0.3 速通路线图（先问清信息 → 并行开工，别线性等）

> 全流程顺序一句话：**确认需求 → Agent 爬资料/语音 与 用户找差分 并行 → 差分先到手 → 资料与数据集就绪后交用户去语音训练 → 训练期间搭完角色 → 训练完接 TTS**。

1. **开梯子**（没有就先解决）。
2. **开工前信息收集**（0.7，说人话）：角色名（含其他形象名，一并爬语音）/ 确认自训语音（默认必做，需下 5G FULL 包，0.5）/ 做几个形象（含愚人节·灵衣·变体）/ 表情图工具默认推荐甩链接 / ffmpeg 有没有 / LingChat 自己装还是帮装（TTS 与手机端现在都不问）。
3. **确认后、开工前，先告诉用户这段时间要做什么**：任务分工明细**只维护在交接清单**（`references/role_handoff_checklist_template.md` 阶段 1，开工时复制为 `<角色名>_交接清单.md` 随进度勾选，见 0.0）——正文不复述，避免多处维护漂移。核心提醒只有一句：**用户侧耗时任务前置**（FULL 包下载第一件），Agent 侧同时开工（爬取留档 / 搭框架 / 写人设）。
4. **差分与数据并行推进**：用户差分到手并完成「命名小图」（2.0 步骤 2）→ Agent 按序号机械重命名放图（2.0 步骤 3）；同时 Agent 搭好语音数据集目录（工作区副本 + 同步整合包 `Data/<模型名>/`，1.3）。
5. **资料与数据集就绪 → 提醒用户去开语音训练**（训练最耗时，最先启动；给 3.1 详细步骤）→ 训练数小时（期间并行，0.3.1）。
6. **训练期间**：Agent 完成角色文件搭建（settings.yml + avatar，第 4 章）→ **角色文件搭好即配大模型 key 测文字聊天**（4.0，不耽误训练）。
7. **训练完成** → 听音色（3.4）→ TTS 接入（第 5 章，默认外部 API）→ 完整语音测试 → 验证清单（第 8 章）收尾。

### 0.3.1 多线并行原则（强制，贯穿全流程，最重要）

> **一句话**：语音训练是纯后台跑数小时，期间**禁止任何一方干等**——一切能并行的工作全部并行，把「训练」当成一条独立后台线，其他所有事在它跑的时候做完。

**两条强制并行线**（开场就要跟用户讲清楚，0.7 并行任务分配 + 本节的组合）：
1. **爬数据期**：Agent 爬语音/资料 ←→ 用户下载 FULL 包 / 表情差分合成工具 / 找差分（用户侧耗时前置，Agent 侧同时开工；分工明细见交接清单阶段 1，0.3 第 3 条）。
2. **训练期（数小时，关键）**：语音训练一旦启动（预处理完成后点「开始训练」），立即双线推进：
   - **用户**：配 LLM key（4.0）→ 打开 LingChat 测试角色**文字聊天**（人设/情绪差分/换装）——**角色文件搭好就测，不用等训练完**；
   - **Agent**：搭角色目录框架 → 重命名差分放图 → 写 settings.yml/角色卡 → 处理头像/愚人节。

**Agent 强制动作（训练期，必须执行）**：
- 语音训练启动后，**主动向用户汇报「角色文件搭建进度」**：搭到哪一步、还剩什么、哪些已可测试；
- **角色文件全部搭建完成 → 立刻提醒用户配大模型 key + 测试文字聊天**（给 4.0 详细步骤），并说明「语音没声音是正常的，模型还在训练」；
- 训练完成前把所有**不依赖训练产物**的步骤全部做完（settings.yml、avatar），训练一结束直接进 TTS 接入；
- **等待用户期间（下载/找差分/命名等）**：Agent 继续推进 Agent 侧可完成项（爬取留档、目录框架、人设初稿），不要干等；用户长时间无响应时主动提醒当前待办（给链接/给步骤），但**不替用户做决定**（0.7 询问纪律）。

**禁止**：训练期间让用户或 Agent 干等；把「配 key 测试聊天」拖到训练完才做；把 TTS 接入以外的步骤留到训练后。

### 0.3.2 三条红线（贯穿全流程，违反即执行失败）

> 以下三条是实战血泪提炼的最高纪律，**任何一步都不得违反**；正文其余「注意/坑」均为普通级别，唯此三条为红线（**另有 0.3.3 开爬闸门，同为硬性纪律且更靠前**）。对应细节见 6.1 #12/#13/#14。

1. **不编造**：示例语音/台词必须来自 fgo.wiki 原文（留档 txt 摘抄，中文 + 日文一一对应），**禁止 Agent 自编台词冒充原语音**（对应 6.1 #13；可验证判据见 4.4.4）。
2. **不覆盖**：改角色 settings.yml 前**必须先 read 当前文件**（用户可能已在软件里改过），只替换用户点名要改的字段，其余原样保留（对应 6.1 #12）。
3. **不替用户定映射**：**差分→情绪映射（图片↔情绪）必须由用户定**，Agent 只做机械搭建与命名，绝不猜名、绝不替用户定死映射（对应 6.1 #14）。**⚠️ 注意区分**：红线 3 只管「图片→情绪」的映射；而 4.4.4 里给示例语音文本按台词内容标注【情绪】差分是**语义标注**（情绪随台词内容走，无需用户逐个确认）——两者不是一回事，不要因为红线 3 把示例标注也推给用户。

### 0.3.3 开爬闸门（硬性停止检查点，违反即执行失败）

> 与三条红线同级、且**比它们更靠前**：**第一次爬取动作（语音页 / 资料页 / 任何联网抓取，包括搜索角色名）之前必须过此闸门**。实战教训：Agent 问题没问完就自顾自开爬，用户直接发火——**问问题阶段没有任何「默认继续」**。

**闸门条件（两个都满足才放行）**：
1. **0.7 的六项问题全部问完且用户逐项回答**：角色名（含其他形象）/ 自训语音 / 做几个形象 / 表情图工具 / ffmpeg / LingChat 安装方式——**没有「没回答就跳过」的项，不能拿「用户没答 = 默认同意」当理由**；
2. **用户明确许可开工**：用户说了类似「可以 / 开始吧 / 确认 / 开工」的话——**沉默、答非所问、只答了部分问题、或只是发了链接，都不算许可**。

**未过闸门的行为（严格）**：
- **禁止一切爬取/联网动作**：搜索角色名、抓语音页/资料页、下载任何文件，一律不行；
- 只允许：继续问完剩余问题、复述已确认的信息请用户确认、等待用户回复；
- 用户长时间无响应 → 可提醒当前待办（给链接/给步骤），但**不能因等不到回复就默认许可开工**。

**过闸门判据（Agent 开爬前自查，逐项打勾）**：
- [ ] 六项问题全部问过，用户逐项有回答
- [ ] 用户明确说了许可开工的话
- [ ] 交接清单阶段 1 的用户侧任务已交代（0.7「确认后、开工前」）

### 0.5 语音大模型下载避坑（必读，下错白下）

> **本 skill 默认必下（0.1：无跳过分支）**：自训语音模型是流程标配，FULL 包（压缩包约 5G，解压后约 12G）为训练必需，**开场第一件事就下载**（0.3 并行原则：最耗时最先下）；不接受训练语音 → 本 skill 不适用，直接告知。

- ⚠️ 官方文档/视频教程里说的「下载 2.7G 那个压缩包就行」**是别人训练好的成品模型，不能拿来训练**——白下。

### 0.8 网络访问与代理（通用方案，自包含，不依赖外部 skill）

> 适用：需要访问外网（GitHub 下载、fandom 爬取等）但直连不通/被墙时。本小节是**通用诊断 + 兜底方案**，不依赖任何外部 skill（旧版 network-proxy-guide 已并入此处）。**多数情况下先试直连，连不上再配代理——别一上来就折腾代理。**

**通用原则（先直连，不行再代理）**：
1. **先试直连**：国内站点（fgo.wiki、modelscope.cn、hf-mirror.com、B站、国内网盘）多数环境直连即可；GitHub / fandom 等国外站**部分地区直连时好时坏，先试一次再决定**；
2. **需要代理的站点**：0.4 资源表里「需梯子」列的那些（GitHub Releases、fandom、HuggingFace 等）——连不上时再走下方方案；
3. **Agent 环境差异**：dsh 沙箱等受限环境可能无直连外网；本地运行的 codex / claude / Trae 等多数可直连——**以实际环境为准，先测再说**。

**确定代理地址（三选一）**：
- **直接问用户**「你的代理（梯子）软件地址和端口是多少？」（最准）；
- Windows 读系统代理：`Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings" | Select ProxyEnable, ProxyServer`；
- 探测常见端口：`netstat -ano | Select-String "7890|7897|10809|8086"`（Clash 常见 7890/7897、v2rayN 常见 10809、部分工具 8086）。

**快速验证代理可用**（把 `<代理地址>:<端口>` 换成实际值）：
```powershell
$env:HTTP_PROXY = "http://<代理地址>:<端口>"; $env:HTTPS_PROXY = "http://<代理地址>:<端口>"
python -c "import urllib.request as u; print(u.urlopen('https://example.com', timeout=15).status)"
```
输出 200 即通。

**受限环境兜底**：若遇到 Windows 自带网络栈 HTTPS 全挂（curl 报 `SEC_E_NO_CREDENTIALS`、Invoke-WebRequest 报「基础连接已经关闭」、Node fetch 无直连），**不要反复重试，先用 Python urllib 直连验证（7.1 模板不设 proxy 即直连），直连仍不通才套代理**。⚠️ 2026-08 实测：本机 GitHub 已可直连（此前误判「必须代理」，实为 token 权限问题）——**「必须代理」类结论先实测再信**。

**git / pip / huggingface 走代理**：`git config --global http.proxy http://<代理地址>:<端口>`（https 同理）；或临时设 `$env:HTTP_PROXY` / `$env:HTTPS_PROXY`（Windows）后再跑 pip / huggingface-cli；macOS/Linux 用 `export http_proxy=... https_proxy=...`。

## 1. 语音数据准备（SBV2 训练集）

### 1.1 音频

- 统一转 wav / 44100Hz / 单声道 / PCM16：`ffmpeg -y -i in.mp3 -ar 44100 -ac 1 -c:a pcm_s16le out.wav`
- 改后缀名≠转格式，必须用工具转（ffmpeg 命令行）
- 单条建议 ≥0.5s（<1s 的指令卡类短语音可用但效果略差）

### 1.2 文本标注 esd.list（核心！）

格式：`音频文件名.wav|角色名|JP|日语原文`（UTF-8 无 BOM）

```
SV295_0_开始1.wav|Van Gogh|JP|うふふ、うへへ
```

- **文本来源**：Mooncell（fgo.wiki）从者语音页的 wikitext（`?action=raw`），结构：
  `|标题N=xxx` / `|日文N=原文` / `|中文N=翻译` / `|语音N=SVxxx_N_xxx.mp3`（⚠️ **键名以实际抓取的 wikitext 为准**：先抓一页 raw 目视确认「日文/中文/语音」键名，再套解析模板，不要凭本表假设）
- **解析要点（主方案：按 VoiceTable 表格切分）**：语音页**多个表格（战斗形象1 2 / 战斗形象3 / 召唤强化 / 个人空间等）各自从编号 1 重新编号**，全局收集会被后面表格覆盖（实战：阿尔托莉雅·卡斯特全量解析只出 34 条，按表格切分后 119 条）。做法：`re.split(r'\{\{#invoke:VoiceTable\|table\|表格标题=([^\n]+)', wikitext)` 按表格切块，**块标题即语音类型**（战斗/召唤强化/个人空间对话/喜欢的东西/讨厌的东西/关于圣杯/生日/活动等），块内再按编号收集 日文/中文/语音（脚本见 7.2）。
- **解析要点（兜底：反向引用跨行匹配）**：仅用于单表/简单页面：`r'\|日文(\d+)=([^\n]*)\n(?:[^\n]*\n)*?\|语音\1=([^\n]*\.mp3)'`（多表格页面不可用，见上）。
- **中文翻译必须一并解析留档**：红线 1 的可验证判据要求「每条示例语音的中文翻译 + 日文原文都能在留档 txt 中 grep 到」（4.4.4）——**中文列（常见键名 `|中文N=`）漏解析则判据不可执行**，解析时中日文都进 `<角色>_语音原文.txt`。
- **文本清洗**（必须）：
  - `{{黑幕|正文|分类}}` → 取正文（生日类语音常见）
  - `{{Ruby|汉字|假名}}` → 取汉字（振假名模板）
  - 其余 `{{...}}` 模板一律删除
  - 去掉半角/全角空格（教程要求，避免影响 BERT 预处理）
- **音频↔文本匹配**：wiki 映射 key 是 `.mp3` 后缀，本地 wav 查询时要 `name.replace('.wav','.mp3')`
- **wiki 无日文原文的音频**（如部分生日语音）：用软件自带 faster-whisper（`third_model/whisper/faster-whisper-ja-anime-v0.3`）转录，与 wiki 中文翻译对照验证

### 1.3 数据集目录

`Data/<模型名>/{esd.list, raw/*.wav}`，raw 里的 wav 文件名与 esd.list 第一列一致。
- **命名规范**：模型名、数据集目录、wav 文件名一律用**英文/拼音**（如 `Van_Gogh`），**路径全程不要出现中文**（安装目录同 0.5，中文路径会报错）。
- **双数据集同步**：工作区维护的数据集副本 + 整合包 `Data/<模型名>/` 训练集**两处都要同步**（esd.list 全量覆盖 + raw 增量复制），只同步一边会导致训练数据不齐。

### 1.4 语音/资料一次性存档（避免重复抓取）

用户说出角色名后，Agent **直接联网搜索并爬取 Mooncell（fgo.wiki）**（不需要用户找资料或发链接），**两个页面同一次爬取一并存档**：

- **先确认条目（爬取前必做）**：先在 fgo.wiki 搜索角色名，确认条目存在且唯一（重名/马甲名易抓错页，如「梵高」vs「克吕提厄·梵高」）；URL 中文路径要按 7.1 的 `urllib.parse.quote` 编码。
- **语音页**：`https://fgo.wiki/w/<角色名>/语音?action=raw`（子页面）→ 解析出全部语音——类型（战斗 / 召唤强化 / 个人空间对话 / 喜欢的东西 / 讨厌的东西 / 关于圣杯 / 生日 / 活动等）+ 日文原文 + 中文翻译 → 存 `<角色>_语音原文.txt`（utf-8 无 BOM）。解析用 1.2 的**表格切分主方案**（脚本见 7.2）。
- **资料页**：`https://fgo.wiki/w/<角色名>?action=raw`（主页面；资料是其中的一个 section，浏览器地址里的 `#资料` 锚点只是定位用，`?action=raw` 拿到的是整页 wikitext）→ 存 `<角色>_资料原文.txt`。**资料页结构**：`==资料==` 标题后是 `{{个人资料` 模板，内部是**键值对**——键在行首（`|键名=`），值可跨多行，直到下一个 `|键=` 或模板结束 `}}`：

| 键 | 内容 | 对应 4.4 人设模板 |
|---|---|---|
| `\|详情=` | 角色简介（一段） | settings.yml 的 `info` 字段，**直接复制粘贴** |
| `\|资料1条件=` / `\|资料1=` / `\|资料1日文=` | 基础数据：身高/体重、出处、地域、属性/副属性/性别 | 【FGO 的从者设定】开头表格（保留原格式） |
| `\|资料2=` / `\|资料2日文=` | 史实生平（真实历史人物）；神话/小说/史诗角色为原典传说 | 【史实生平】或【原典】 |
| `\|资料3~6=` / `\|资料3~6日文=` | 技能/宝具/设定详解、人物剖析 | 【FGO 的从者设定】正文（转述第二人称） |

> `{{个人资料` 模板只含上面这些键；【主线剧情的记录】【主线物语的记录】【活动任务的记录】不在这里——主线/活动经历需按 4.4.2 的指引另行检索（活动记录可查「从者登场剧情一览」页），【迦勒底的人际关系】从语音页的角色互动部分概括。

后续填人设、写示例语音时直接读这两个 txt，**不要反复爬取，更不要凭记忆填**（红线 1，6.1 #13）。**全量补全**（灵衣/新皮肤/漏下载语音，如矿工梵高 SV428 并入同一模型）→ **进阶版 lingchat-role-maker-pro 第 1 章**。

### 2.0 获取差分（角色表情图）

> **面向新手的话术**：用户不知道「差分」是什么——先解释为「**角色各种表情的图片**（高兴/生气/害羞…）」。
> **前置**：先按 2.1 完成灵基确认、目录框架与放图清单，再把本节的链接与步骤给用户——放图清单是用户命名差分的对照依据。

**获取工具（推荐，直接甩链接）**：B站大佬阿良良睦历的「表情差分合成工具」
- 下载（二选一）：百度网盘 https://pan.baidu.com/s/1m6tv52y5FJfz-bgk7OHDfw?pwd=fgo1 / 夸克 https://pan.quark.cn/s/a6162b75285b?pwd=E11Z
- 教程：BV1T8g56LEnb
- 💡 **提醒**：如果下载了同位大佬开发的「FGO 全角色桌宠软件」（BV1C48u6rEMq），也可用它的内置工具拆分差分。

**拿到差分之后怎么做（告诉用户照做）**：

1. **保存到工作区单独文件夹**：Agent 先建好工作区目录骨架（见下），让用户把差分导出到 `<workspace>/lingchat/<角色名>/03_素材/差分原图/`（命名小图和大图分目录存放），别和角色文件混在一起。
2. **「命名小图」流程（推荐，实战最优）**：对照目录里的「放图清单」（20 情绪 + 头像，见 2.1 与 `references/avatar_情绪文件名清单.md`），把差分小图命名为「情绪_序号」（如 高兴_01、正常_06），**命名一张划一张**，防漏防重（缺哪个情绪一目了然）。
3. **大图交给 Agent 按数字序号映射自动重命名放图**：小图序号 = 大图序号（`portrait_NNN` 是差分合成工具导出**大图**的默认文件名，序号即导出编号；如 高兴_01 → portrait_01 → 高兴.png），Agent 机械执行。
4. **一个情绪多张小图**（如 高兴_01、高兴_02）：先全部按序号命名保留；**最终每个情绪只放一张大图进角色目录**，多张时让用户挑一张，其余留在差分原图文件夹备查——Agent 不替用户选。
5. **识图纪律**：**默认不用识图看用户的差分，完全按数字序号机械重命名**；仅当用户明确要求识图比对时才用视觉工具。

> **工作区目录骨架（Agent 开工时一次建好，仅为中转，不是最终落图处）**：
> ```
> <workspace>/lingchat/<角色名>/
> ├── 01_爬取留档/          ← 语音原文.txt / 资料原文.txt（1.4）
> ├── 02_语音数据集/        ← 数据集工作区副本 esd.list + raw/（1.3）
> ├── 03_素材/差分原图/     ← 用户导出的差分（小图/大图分目录）
> └── 04_角色文件/          ← （可选）角色搭建的临时产物
> ```
> **最终落图处是 LingChat 角色目录 `data/game_data/characters/<角色>/avatar/`**（4.1），工作区目录只是中转，别把两处混淆。

### 2.1 素材前置步骤（先做：确认灵基 → 搭框架 → 放图清单；差分与写人设两条线并行）

> **执行顺序**：本小节（搭框架/放图清单）在 2.0（用户获取差分）**之前**完成——放图清单是用户「命名小图」的对照依据。

1. **Agent 先向用户确认灵基数量**：做几个灵基/服装？**包不包括愚人节、灵衣、其他活动变体**（如矿工梵高 SV428）？每套服装 = 一个 avatar 子目录（4.1）。
2. **Agent 在 LingChat 角色目录搭框架（留空）**：按 4.1 建 `avatar/` 主目录 + 各服装子目录，先不放图。
3. **每个目录放一张「放图清单」**：在空目录里放一个说明文件（如 `放图清单.txt`），列出该目录应有的文件名（20 情绪 + 头像，以 `references/avatar_情绪文件名清单.md` 为模板），用户找差分时按清单放图、比对命名，不用反复问 Agent。
4. **两条线并行**：用户去找差分/立绘（2.0）的同时，**Agent 开始写角色卡设定**（4.4 人设/示例语音，基于已爬取的资料页留档 1.4）——找差分（人肉活）与写人设（脑力活）互不等待；语音训练同样数小时（0.3.1 并行）。完整分工明细见交接清单阶段 1（0.7）。

### 2.2 立绘来源（按优先级）

- 透明底差分：**表情差分合成工具产出** ✅ 直接用（2.0）
- 官方立绘（fgo.wiki `梵高初始/一破/三破/满破.png`、atlasacademy CharaGraph）：**全是带背景的**（FGO 原版黑底），LingChat 立绘要透明背景 → 需抠图或不用
- **全身立绘 + 透明底愚人节立绘：fandom**（https://fategrandorder.fandom.com/wiki）——fandom 一般有从者**全身立绘**，也有**透明底的清晰从者愚人节立绘**（用户要愚人节立绘做服装时来这找，可做额外服装，半身/全身都能显示，object-fit: contain + 底部对齐）。
  ⚠️ **爬取不保证成功**（图片众多，全身/愚人节立绘都可能失败）；**用户自己找时**：打开从者个人页面 → **Gallery 标签页** → 翻到**最底部** → 保存图片并转换格式（官方立绘带背景需抠图）

> ⚠️⚠️ **愚人节立绘来源纪律（血泪，实战踩坑）**：**Mooncell（fgo.wiki）的愚人节卡面（`<角色>愚人节卡面.png`）是带背景不透明的，不可用**——别自作聪明下载它复制重命名（用户一眼看出没法用）。要做愚人节立绘**只能去 fandom 找透明底**（https://fategrandorder.fandom.com/wiki/<角色英文名>，**需梯子**），且 **fandom 的愚人节立绘有两个版本（一个清晰一个模糊，容易出错），建议让用户自己去挑**（Agent 不代爬代找）。**用户提出做愚人节立绘需求时，立刻说清这一点**，并把「去 fandom 下载透明底愚人节立绘」加进用户待办（0.7），给出网址 + 提醒梯子。拿到图后验证透明底：PIL 检查四角 alpha=0。

### 2.3 头像

需要一张头像图，**没有硬性尺寸规定**（参考用正方形，约 388x388 起即可）。**获取路径（按序）**：① 用户自己裁好的图直接放；② 用户没裁 → **Agent 用 PIL 从该服装立绘正方形居中裁剪生成**（`Image.open → convert('RGBA') → 取短边 center_crop → resize(512,512) → save 头像.png`；立绘若带背景先确认透明底，裁前告知用户）；③ 从卡面/立绘裁剪。**不同服装（灵基再临）可以用不同头像**——每套服装目录里放各自的 `头像.png` 即可（见 4.1）。

### 2.4 单图服装与情绪命名统一（愚人节类服装）

- **单图服装**（愚人节类）：一张整图复制到全部情绪文件（20 个情绪同名图片 + 头像），人物卡加对应 clothes 条目。**角色图片 png / webp 均可**（LingChat 按文件名找图，不挑扩展名；梵高成品愚人节目录里的 `.webp` 是**历史遗留的忘改格式，不是标准格式**，新做角色统一用 png，见 `references/avatar_情绪文件名清单.md`）。有兴趣和能力的用户可以用 AI 或自行绘制为愚人节角色也加上表情差分。
- **情绪文件命名统一无后缀**：历史遗留的 `_full` 等后缀一律改成标准情绪名（伤心.png/高兴.png…），LingChat 按情绪名找文件，统一格式好维护。
- **头像按服装区分**：每套服装目录放各自裁剪好的 `头像.png`（见 2.3），一套一像。
- **立绘补图 / 全身化**（角色移动露白穿帮的进阶解法，改 scale 不够时用）→ **进阶版 lingchat-role-maker-pro 第 3 章**。

## 3. SBV2 模型训练（VoiceSpeechMaker 整合包）

### 3.1 训练（WebUI）

> 训练环境 = 0.5 的 Style-Bert-VITS2-FULL 包（解压即 VoiceSpeechMaker-core-fork 整合包，含 WebUI 与训练底模，**一个包搞定**）；2.7G 成品包是别人训练好的模型，不能拿来训练。**用户不需要额外下载任何推理模型**。

> **⏱️ 训练时长预期（别以为卡死）**：取决于数据量（目标 30min+/200 条+）与显卡——集显/8GB 显存 + 全量语料可能 **10 小时+**，中高端 N 卡约 4~8 小时，均属正常。终端窗口持续滚动 step 即正常训练中，**不要因为「跑得久」去关窗口/重启**（黑色窗口点了会暂停，按 Enter 恢复）。

1. 双击 `.启用全部功能.bat` → 浏览器 http://127.0.0.1:7860/ → 「训练」tab
2. 模型名称 = 数据集目录名（如 `Van Gogh`）
3. `使用 JP-Extra 版本` 勾选（全日语角色）；**批量大小按 GPU 专用显存选，建议选比专用显存低一档**：8GB→1、12GB→3（取最大承受值减一）。**查看专用显存**：`Ctrl+Shift+Esc` 打开任务管理器 → 左侧「性能」→「GPU」查看；**Agent 可自查**：`Get-CimInstance Win32_VideoController | Select-Object Name, AdapterRAM`（Name=型号，AdapterRAM 字节数 ÷1024³≈显存 GB）；**不清楚显存或不想麻烦 → 直接选最小档**，一样能训，只是慢一点
4. 音量规范化勾选 → 「执行自动预处理」（第一次会下载 BERT 日语模型）
5. 「开始训练」→ 进度看黑色终端窗口
6. ⚠️ **Windows 坑**：点黑色终端窗口会**暂停训练**，按 Enter 恢复
7. ⚠️ **预处理完成 ≠ 训练启动**：日志出现「All preprocess finished!」只代表预处理全完成，**训练要再点「开始训练」才启动**；点完确认训练真的在跑：`Get-CimInstance Win32_Process -Filter "Name='python.exe'"` 应能看到 `train_ms_jp_extra.py` 进程，或 `Data/<模型>/models/` 下出现新的 G_/D_ 权重（非底模）。

### 3.2 续训

训练到某步停了想继续：回「训练」tab → 模型名 → **把「轮次数」调大**（如 100→200）→ 开始训练 → 自动从最新 `G_XXX.pth` 断点续训，无需重新预处理。

### 3.3 产物与测试

- 产物：`model_assets/<模型名>/`（config.json + `<模型名>_eXXX_sXXXX.safetensors` + style_vectors.npy）——三件齐全才能用
- 测试：「语音合成」tab → 模型列表点 **「刷新」**（训练后新增的模型要刷新才出现）→ 选模型/说话人 → 输入日语合成

### 3.4 训练质量评估（怎么判断训得好不好）

- **客观参考**：WebUI「模型评测」界面可合成试听（挑不同文本：长句/短句/语气词/数字），对比训练前后差异。
- **唯一可靠的评估 = 自己去听**：在「语音合成」tab 多试几条（日常对话、长难句、笑声语气词），凭听感判断音色像不像原角色、语气自不自然、有没有电流音/吞字/崩音。不要只看 loss 数值（终端里 step/loss 只作趋势参考，持续下降即可，最终以听感为准）。
- **不满意 → 改语料重训，不是改参数**：
  - 音色不像/泛化差 → **扩充语料库**（目标 30 分钟+/200 条+）：官方语音全量补全 → 进阶版第 1 章；剧情语音合集 BGM 分离流水线 → 进阶版第 2 章
  - 有崩音/奇怪发音 → **缩减语料**：按筛选标准剔除不合格段后重训（进阶版 2.4）
  - 只是部分句子不行 → **续训**（3.2 调大轮次从断点继续）即可，不必全量重训

### 3.5 参考音频功能（风格参考）

若用户问起：**直接说忽略即可**（对长文本整体风格延续作用有限，还需额外下载模型，不值得折腾）。

## 4. LingChat 角色搭建（核心）

### 4.0 LingChat 本体准备（首次使用）

1. **安装方式先询问用户**：给 GitHub Releases 链接自行安装，还是 Agent 帮忙下载安装到指定位置？（0.4 地址；**下载≠克隆**；需要梯子）
2. **配置语言大模型 API key（角色文件搭好即配，不用等训练完）**：LingChat 对话由 LLM 驱动——**key 在角色文件搭好后就配**（与语音训练并行，见 0.3.1 多线并行原则），开工时装 LingChat 主要为了拿 `data/game_data/characters` 目录搭框架；配法：**「游戏配置 → 高级设置 → 大模型管理」** 填至少一个 LLM API key（0.2 前置条件 4），**不配无法与角色对话**；配好 key + 角色结构搭好即可先文字聊天（语音模型后补，第 5 章）；**视觉大模型 API key 可选择使用**，不开也能用，只是少图像理解能力（想配的话：key 获取与配置方案见进阶版 lingchat-role-maker-pro 第 11 章，**用户问起视觉 key 时再加载**，默认不展开）。**key 安全纪律**：key 由用户在 LingChat 内手输，Agent 不触碰、不写入任何脚本/文件、不向用户回显。
3. **音乐与背景素材**：LingChat 设置里可更换音乐/背景，素材可在 **chaldea** 获取（0.4 的 chaldea，内含从者 BGM/背景等资源，用户自行挑选喜欢的即可）。

### 4.1 目录结构

> 框架在素材阶段就搭好（见 2.1 素材前置步骤），这里列出的是完整结构；每个目录会放一张「放图清单」供比对放图。

```
characters/<角色文件夹>/
├── settings.yml
└── avatar/
    ├── 头像.png            ← 20 情绪 + 头像 = 21 张
    ├── 高兴.png 伤心.png ...（20 个情绪）
    ├── <服装2>/            ← 每套服装同样 21 张（可复用一套差分；**头像也可不同**——灵基再临用不同头像）
    └── <服装3>/
```

> ⚠️ **服装子目录必须在 `avatar/` 里面**（`characters/<角色>/avatar/愚人节/`），**不要建在 `characters/<角色>/` 与 avatar 平级**——LingChat 按 `avatar/<服装名>/` 找服装图，平级会导致 get_avatar_file 找不到图而报错（实战踩过，血泪）。

> **命名差异（重要）**：**语音侧**（模型安装目录/数据集/素材）必须全英文（0.5 / 1.3）；**LingChat 本体侧**的角色文件夹、情绪图片、头像等文档命名**中英文皆可**（示例里的「梵高」「高兴.png」就是中文，没问题）。

### 4.2 情绪槽（固定 20 个，后端协议字段不能改）

`兴奋 厌恶 伤心 害怕 害羞 平静 心动 惊讶 慌张 担心 无奈 生气 疑惑 紧张 自信 认真 调皮 羞耻 高兴 正常` + `头像`。

> **✅ 数量决策规则（消除歧义，务必先读）**：**新角色默认 = 标准 20 情绪 + 头像 = 21 张/套**。`references/avatar_情绪文件名清单.md` 里梵高目录的 22~24 个文件（多出的闭眼/放松/感动/微笑是**旧版遗留情绪**）是**复刻/参考梵高时**才照抄的数量，**不是新角色的标准**——新角色就按 20 情绪 + 头像（21 张）做，别把梵高的遗留情绪当标配。

> **参考文件**：梵高 v1.0 各服装目录的真实文件名清单见 `references/avatar_情绪文件名清单.md`（含**旧版遗留情绪**案例：闭眼/放松/感动/微笑——旧版情绪槽遗留，未改源码，新版不触发但无害；及愚人节 .webp 历史遗留案例）。

- **AI 输出未知情绪** → 自动回退「正常」（不报错，但多余表情文件不会被触发）
- 想加新情绪（如 感动）→ 必须改源码 `src/controllers/emotion/config.ts`（EMOTION_CONFIG_EMO + EMOTION_CONFIG）并**重新编译**（需 pnpm + Rust 工具链）——不编译则文件无害但永远不触发
- **旧版遗留情绪**（如梵高文件里的 闭眼/放松/感动/微笑）：LingChat 旧版情绪槽比新版多，这些文件**新版不触发但无害**，可保留也可删除（梵高成品就是没删）。**不是标准情绪**，Agent 照抄参考角色清单即可，别当成标准 20 情绪去增删
- **服装子目录必须放齐 20 情绪 + 头像**：get_avatar_file 对子目录缺图（除「平静」回退「正常」外）直接报错

### 4.3 settings.yml 字段语义速查（Rust 严格类型！）

> ⚠️ **字段顺序以 4.4.1 为准**（两个成品 settings.yml 顺序一致，母版见 `references/settings_van_gogh.yml`）——本节只解释**每个字段的语义与类型陷阱**，**不要按本节表格的排列顺序写文件**。

| 字段 | 语义 | 类型陷阱 |
|---|---|---|
| `ai_name` | 角色名 | 字符串 |
| `ai_subtitle` | 副标题/职阶（如 Foreigner / Pretender） | 字符串 |
| `user_name` / `user_subtitle` | 御主名 / 御主副标题 | 由用户自定义，别替用户编 |
| `title` | 角色称号（一句，如「星月夜的少女画家」） | 字符串 |
| `info` | 简介：来自 Mooncell 资料「详情」**直接复制粘贴**，不自行概括 | 多行用 `\|-` |
| `body_part` | 空对象占位 | `{}` |
| `scale` / `offset_x` / `offset_y` | 立绘缩放/偏移 | ⚠️ **f64，必须浮点字面量**（`1.0`/`0.0`，写 `0` 解析失败）；FGO 半身立绘默认 1.0——官方默认 1.4 是给全身立绘的，半身用 1.4 会填满整个屏幕；若做全身立绘则提醒用户自行调整 |
| `scale_p` / `offset_x_p` / `offset_y_p` | 桌宠模式缩放/偏移 | 同上，浮点 |
| `clothes_name` | 当前默认服装名 | 无则 `null` |
| `clothes` | 服装列表，每套 = `name` + `prompt`（外貌/气质描述） | 列表，顺序即 4.4.1 中的示例写法 |
| `voice_models` | 语音模型配置 | **必须 20 字段齐全**，见 `references/voice_models_20字段.md`（注意 `'0'` 字符串 / `0` 整数 / `null` 三种类型） |
| `tts_type` | TTS 方案 | 速通版默认 `sbv2`（外部 API，第 5 章）；本地 TTS 为 `localsbv2api`（pro 第 5 章） |
| `voice_lang` | 语音语言 | 日语角色填 `ja` |
| `thinking_message` | 思考气泡文案（角色名+在做什么） | 贴合角色性格（如「梵高亲在紧张地找话题...」） |
| `bubble_top` / `bubble_left` | 气泡位置 | 数字 |
| `system_prompt` | **人设正文：三明治结构（见 4.4.2），不带【情绪】差分、不带日语翻译** | 多行用 `\|-` |
| `system_prompt_example` | 新版示例：**无日语**（格式见 4.4.3） | 与 old 一一对应 |
| `system_prompt_example_old` | 旧版示例：每条正文后加 `<日语翻译>`（配合日语语音） | 与 new 一一对应 |
| `character_folder` | **必须与角色文件夹名一致！** | 字符串 |

> **写文件时**：按 4.4.1 的字段顺序 + `references/settings_van_gogh.yml` 母版照抄结构，4.3 只用来查字段含义与类型陷阱。

### 4.4 人设编写要点与通用模板（参照成品：梵高 / 但丁 settings.yml）

> **模板来源**：以下格式总结自两个已跑通的成品——`characters/梵高v1.0/settings.yml`（147 行，已收录至 `references/settings_van_gogh.yml`）与 `characters/但丁/settings.yml`（112 行）。两者**顶层字段顺序完全一致**，仅内容量不同（梵高 6 套服装 / 但丁 5 套）。**梵高 v1.0 成品 settings.yml 已收录在 `references/settings_van_gogh.yml`**（含 voice_models 完整 20 字段，字段说明见 `references/voice_models_20字段.md`）；**但丁版板块写法参考（含【主线剧情的记录】原文段落，及与梵高版的主要差异）见 `references/settings_dante.yml`**——注意该文件是**结构 + 板块示例母版，不是完整成品**（完整内容需按 1.4 爬取 fgo.wiki 资料后填写）。新角色的人设部分照此模板填写即可。

#### 4.4.1 settings.yml 完整字段顺序（照抄防漏，字段说明见 4.3）

```yaml
ai_name: 梵高                # 角色名
ai_subtitle: Foreigner       # 副标题/职阶（但丁: Pretender）
user_name: 用户填写              # 御主名，由用户自定义
user_subtitle: Master        # 御主副标题
title: 星月夜的少女画家       # 角色称号（但丁: 神曲的作者，吟游诗人）
info: |-                     # 简介（多行用 |-；概述身份，此处文本统一来自Mooncell的角色资料的角色详情部分，直接复制粘贴即可，不需要自行概括）
body_part: {}                # 空对象，占位
scale: 1.0                   # 立绘缩放 f64（浮点字面量，见 4.3）
offset_x: 0.0

#### 4.4.4 编写要点

- **角色原资料**：填写 wiki 上角色的**原资料**（抓取方法见 1.4：`|详情=` → info、`|资料1~6=` → 各人设板块），涵盖游戏性（职阶/星级/宝具/技能定位）和剧情性（真名/出身/人物关系/性格/口癖），并**转述为第二人称设定格式**（「你是…」），写入 system_prompt。

- **语音示例多表情差分**：写 system_prompt_example 时，参照现有角色示例，**一句话中插入多个【情绪】差分变化**（如「【无奈】…【正常】…【紧张】…【调皮】」），不要一条情绪走到底。

- **原语音摘抄默认规则（红线 1，必须执行）**：根据先前记录的语音内容 txt 文件做关键原语音摘抄，**示例语音（system_prompt_example / example_old）必须全部为角色原有语音**（原句摘抄或原句精简拼接，中文翻译 + 日文原文一一对应），**除非用户明确要求自编/改编**——**禁止 Agent 自编台词冒充原语音**（实战血泪：编造示例台词被用户一眼识破；正确做法：从语音页留档 txt 逐条摘抄原句，按内容标注【情绪】差分）。**可验证判据**：每条示例语音的中文翻译与日文原文，都必须能在留档 txt 中 grep 到（允许原句精简拼接）；填写完成后 Agent 逐条自查并报告核对结果，任何一条对不上即重写。**「喜欢的东西」「讨厌的东西」默认填写**（除非用户明确要求去掉）；其他（对话 / 关于圣杯 / 生日 / 召唤等）根据用户需求填写。
- **写入验证**：人设与示例填完后用 `yaml.safe_load` 验证（6.1 #13），并检查块标量内每行缩进一致；示例语音/台词必须爬 fgo.wiki 原文，禁止凭记忆填（红线 1，6.1 #13）。

## 5. TTS 语音接入（默认外部 API）

### 5.0 方案默认（先说明，再给步骤）

> **什么时候告知用户**：**训练完成、角色快搭好时才说**（0.7 现在不问）。新手不知道 TTS 是什么——先解释「TTS = 让角色开口说话的声音」。

- **速通版默认「外部 API」方案**：训练产物（safetensors）放进外部引擎**直接用，无需转换**，听感最接近训练效果；代价是**每次要先手动开 `.启用API服务.bat` 黑窗口**（关了就没声音）。
- **备选「内置本地 TTS」**（只开 LingChat 一个软件、零外部依赖、手机端必需，但要转 .sbv2 且感情表现略弱）→ 用户在意这些时，加载**进阶版 lingchat-role-maker-pro 第 5 章**，随时可切换（settings.yml 改 `tts_type` 即可）。

### 5.1 外部 API TTS 接入步骤（速通版默认）

1. 启动 VoiceSpeechMaker `.启用API服务.bat`（监听 0.0.0.0:5000，保持窗口开着）
2. LingChat 设置 → 角色 → 齿轮 → 「语音设置」→ **TTS 类型选 SBV2**，模型名称填训练模型名（如 Van Gogh），语音语言 ja
3. 全局设置里 SBV2 服务地址填 `http://127.0.0.1:5000`
4. 启动顺序：先开语音 API 服务，再开 LingChat（无需刷新 TTS）

其他外部引擎：sbv2api（/synthesize）、gsv、aivis、indextts、opentts 等。

### 6.1 必踩坑（高频内联；每条给根因+修法，详细展开见进阶版第 6 章对应编号）

> ⚠️ **编号说明**：本节 #1~#17 是**速通版本地编号**；进阶版 lingchat-role-maker-pro 第 6 章是**全局编号 #1~#43**——两套编号不是同一个坑（如本节 #13=禁止凭记忆，pro 的 #13=Start-Process 路径空格）。本节的坑在 pro 版里的对应：BOM #1、中文路径 6.1 引言、沙箱 #4、网络 #6、转义 #10、解析 #14、后缀 #15、title 规范化 #20、whisper 兜底 #21、缺图 #17、解释器 #19、改文件纪律 #24、禁止凭记忆 #25、情绪映射 #26、numpy #36、config 污染 #37、预处理≠训练 #43。

1. **BOM 坑**：PowerShell `Set-Content -Encoding UTF8` 会加 BOM → serde_yaml 解析失败 → **LingChat 启动闪退**。所有写入 YAML/配置文件**用 Python 写（utf-8 无 BOM）**；诊断：检查文件头 3 字节是否 `EF BB BF`。
2. **中文路径坑**：语音模型安装目录、训练素材/数据集路径含中文会报错，必须全英文（拼音可）；**LingChat 角色文档（角色文件夹/情绪图/头像）命名中英文皆可**，两者别混淆。
3. **沙箱权限**：写工作区外目录（C:\Users\...、D:\SoftWare\...）被拒（Permission denied）→ 不是文件锁！用 `sandbox_permissions: "danger-full-access"` + 一句话 justification 重试。
4. **网络代理**：curl（schannel）HTTPS 报 `SEC_E_NO_CREDENTIALS`；Invoke-WebRequest 报「基础连接已经关闭」；Node fetch 无直连——**这类报错不要反复重试，直接换 Python urllib + ProxyHandler 模板（7.1）**（完整方案、验证命令与 git/pip 配置见 0.8，自包含不依赖外部 skill）；fgo.wiki、modelscope.cn 等国内站可直连。
5. **脚本转义**：模板字符串（反引号）吞反斜杠 → 写脚本一律用数组 join 构造（每行一个数组元素），Python 路径用正斜杠、换行用 `chr(10)`、正则里 `\s`→`[ \t]`。
6. **语音页解析**：fgo.wiki wikitext 多表格、每个表格从编号 1 重新编号 → **按 VoiceTable 表格切分后块内收集**（1.2 主方案）；反向引用跨行正则只作单表兜底。
7. **后缀不匹配**：esd.list 查询时 wiki 是 `.mp3`、本地是 `.wav` → `name.replace('.wav','.mp3')` 后再查。
8. **MediaWiki title 规范化**：`action=query` 返回的 `page.title` 是**中文前缀「文件:」**且下划线被规范化为空格 → 取 key：`title.split(':', 1)[1].replace(' ', '_')`，**不能用 `title[5:]` 切片**（会把文件名首字符切掉，报 `no url`）。
9. **灵衣/部分语音表日文为空**：→ 兜底用整合包自带 faster-whisper（`third_model/whisper/faster-whisper-ja-anime-v0.3`）转录，文本标注「whisper 转录，未经人工校对」。
10. **服装子目录缺情绪文件会报错**（平静除外）→ 每个服装目录放齐**该角色应有的全部情绪图 + 头像**（数量规则见 4.2 决策规则：新角色 = 标准 20 情绪 + 头像 = 21 张；仅复刻参考角色时才以该目录实际清单为准）。
11. **解释器选错**：系统 python 可能没装 pyyaml/PIL/torch → 轻量解析（urllib/re/ffmpeg 调用）系统 python 够用；重型库（torch/demucs/whisper）**必须用 VoiceSpeechMaker 的 `env\python.exe`**。
12. **改文件纪律（红线 2）**：改角色 settings.yml 前**必须先 read 当前文件**（用户可能已在软件里改过，凭记忆重写会覆盖丢失用户设置，数据库无备份）；只替换用户点名要改的字段，其余原样保留。
13. **禁止凭记忆（红线 1）**：示例语音/台词**必须从 fgo.wiki 爬原文填写**，禁止 Agent 自编台词冒充原语音（实战血泪：编造被用户一眼识破）；填完用 `yaml.safe_load` 验证。
14. **情绪映射纪律（红线 3）**：**差分→情绪映射必须由用户定**，Agent 只做机械搭建（按参考角色清单机械命名），绝不替用户定死映射、绝不猜名（视觉模型对动漫微表情识别精度极低，实战整套配错被用户看穿）。
15. **numpy 坑**：训练启动即崩（只有 torch_cuda.dll 堆栈、无 Python Traceback）→ **SBV2 训练必须 numpy 1.x（1.26.4）**；`pip install numpy==1.26.4` 后重启 WebUI/API。
16. **config 污染**：训练固定 step 崩溃（`ScatterGatherKernel.cu:145` + 异常码 0xc0000409）→ 训练 config.json 的 data 段被污染（training_files/spk2id 指向其他模型）→ 改回本模型的 train.list 与 speaker。
17. **预处理≠训练**：日志「All preprocess finished!」后**要再点「开始训练」**；点完确认 `train_ms_jp_extra.py` 进程存在或 `Data/<模型>/models/` 出现新权重。

### 7.2 Mooncell（fgo.wiki）语音页与资料页解析

```python
# 语音页解析【主方案：按 VoiceTable 表格切分】（见 1.2）
# ⚠️ 先目视确认 wikitext 键名（日文/中文/语音）再跑；中文列必须解析进留档（红线 1 判据需要）
import re
def clean(text):                       # 文本清洗（1.2：黑幕取正文 / Ruby 取汉字 / 删其余模板 / 去空格）
    text = re.sub(r'\{\{黑幕\|(.*?)\|[^}]*\}\}', r'\1', text)
    text = re.sub(r'\{\{Ruby\|(.*?)\|.*?\}\}', r'\1', text)
    text = re.sub(r'\{\{[^}]*\}\}', '', text)
    return re.sub(r'[ \u3000]+', '', text)

rows = []                              # (类型, 日文, 中文, mp3文件名)
blocks = re.split(r'\{\{#invoke:VoiceTable\|table\|表格标题=([^\n]+)', wikitext)
# blocks 形如 [前导, 类型1, 块1, 类型2, 块2, ...]（前导通常为空，跳过）
for i in range(1, len(blocks), 2):
    vtype, body = blocks[i].strip(), blocks[i+1]
    for m in re.finditer(r'\|日文(\d+)=([^\n]*)\n(?:[^\n]*\n)*?\|语音\1=([^\n]*\.mp3)', body):
        num, jp, fn = m.group(1), m.group(2), m.group(3)
        cm = re.search(r'\|中文' + num + r'=([^\n]*)', body)   # 中文键名以实际 wikitext 为准
        rows.append((vtype, clean(jp), clean(cm.group(1)) if cm else '', fn))
jp_by_file = {fn: jp for _, jp, _, fn in rows}   # 日文按 mp3 索引（esd.list 用）
zh_by_file = {fn: zh for _, _, zh, fn in rows}   # 中文按 mp3 索引（留档/示例判据用）
```

# 语音页解析【兜底：反向引用跨行正则】（仅单表/简单页面，见 1.2）
import re

```python
# 资料页解析（{{个人资料 模板键值对，见 1.4）
# 依赖：urllib/re 即可；wikitext = 1.4 的 ?action=raw 抓取结果
import re
sec = wikitext.split('==资料==', 1)[1]

def clean(text):                        # 清洗：去脚注/模板，保留 Ruby 汉字
    text = re.sub(r'<ref[^>]*>.*?</ref>', '', text, flags=re.S)
    text = re.sub(r'<ref[^>]*/>', '', text)
    text = re.sub(r'\{\{Ruby\|(.*?)\|.*?\}\}', r'\1', text)
    text = re.sub(r'\{\{[^}]*\}\}', '', text)
    return text.strip()
profile = {}
for part in re.split(r'\n(?=\|[^=\n]+=)', body):   # 按行首 |键= 分割（值可跨行）
    key, _, val = part.partition('=')
    key = key.lstrip('|').strip()
    if key: profile[key] = clean(val)
# profile['详情'] → info 字段；profile['资料1'] → 基础数据表；profile['资料2'] → 史实生平……

### 7.3 ffmpeg 批量转 wav

```python
import subprocess, glob, os
ffmpeg = r'<ffmpeg 可执行文件路径>'   # 先检查本机有没有 ffmpeg；没有则下载 FFmpeg-Builds（GitHub BtbN/FFmpeg-Builds）解压
out = '<输出目录>'                  # ⚠️ 必填：输出目录（不存在则先 mkdir），漏定义会 NameError
os.makedirs(out, exist_ok=True)
for mp3 in glob.glob(r'<音频源目录>/*.mp3'):
    wav = os.path.join(out, os.path.splitext(os.path.basename(mp3))[0] + '.wav')
    subprocess.run([ffmpeg, '-y', '-i', mp3, '-ar', '44100', '-ac', '1', '-c:a', 'pcm_s16le', wav], capture_output=True)
```
